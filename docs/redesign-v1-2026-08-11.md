# AgentBridge 重新设计 v1

日期：2026-08-11
状态：设计基线，按阶段实施

## 1. 为什么重新设计

当前 0.9.0.622 是“连接器 MVP 预览版”：13 个白名单 MCP 工具、4 个专业 Skill、Planner v1、Markdown/TXT 知识问答、五层诊断和自动化 CI。它能跑通，但对照 2026 年智能体与大模型的能力，存在四个结构性短板：

1. **Planner v1 依赖模型输出自编 JSON 决策协议**，再由 `PlannerDecisionParser` 解析。现代模型（OpenAI Responses、Claude tool use、本地 Qwen/DeepSeek 等）已经原生支持工具调用和结构化输出，自编协议脆弱、易漂移，应替换为原生 tool-calling 循环。
2. **知识库只有关键词/分块检索**，没有向量检索、重排和 OCR，无法应对 PDF、扫描规范和大型规范库。
3. **几何算法全部自研**（`geometry_normalizer`、`outer_outline` 等），能处理矩形 fixture，但双线墙中心线、门窗补口、围合空间需要健壮的平面图内核；应引入 shapely 2.x 作为几何底座，而不是继续手写。
4. **产品一致性与验收缺口**：UI 版本常量曾停在 0.8.0 与发布版本不同步；AutoCAD 多版本打包刚支持；真实 DWG 验收矩阵 D01-D10 全部未跑；没有可复用的 eval 基准。

## 2. 目标架构 v2

```text
┌────────────────────────────────────────────────────────────┐
│ MCP Hosts: Codex / Claude Code / 其他 MCP 客户端            │
└───────────────┬────────────────────────────────────────────┘
                │ stdio / Streamable HTTP
┌───────────────▼────────────────────────────────────────────┐
│ cadmcp（独立 MCP Server，工具唯一实现）                     │
│ 13+ 白名单工具 · 权限票据 · 结果协议 · 语义能力             │
└───────┬───────────────────────────────────┬────────────────┘
        │ LocalToolBridge                    │ 直接工具调用
┌───────▼───────────────┐        ┌───────────▼────────────────┐
│ AutoCAD 插件（多版本）│        │ copilot_backend             │
│ AICHAT/AISNAPSHOT     │        │ Agent Loop v2（原生工具调用）│
│ 快照/事务/回滚        │        │ Planner v2 · Skills v2      │
└───────────────────────┘        │ 知识 RAG · 诊断 · Evals     │
                                 └───────────┬────────────────┘
                                             │ 统一 Provider 接口
                        ┌────────────────────▼─────────────────┐
                        │ OpenAI / Claude / DeepSeek / MiniMax  │
                        │ Ollama / 企业内网兼容 / Embedding     │
                        └──────────────────────────────────────┘
```

设计原则：

- **MCP 是唯一集成面**：所有外部 Host 通过 cadmcp 进入；backend 是内部 Agent/Planner 运行时，不重新发明外部协议。
- **工具调用原生化**：Planner v2 直接使用模型 tool-calling，不再解析自编 JSON 决策；写工具仍保留 dry-run → 一次性授权 → 事务 → Handle 校验 → 回滚。
- **几何底座标准化**：`cadmcp/domain/geometry/` 基于 shapely，所有轮廓、中心线、补口、围合算法建立在统一几何内核上。
- **知识检索混合化**：关键词 + 本地/远程 embedding + 可选重排，来源引用与拒答规则保留并强化。
- **可观测与可评估**：OpenTelemetry 追踪、统一 trace id、Golden DWG fixture 回归和 Precision/Recall 报告。

## 3. 分阶段改造

### A. 基座一致性（约 1 周）

- 版本单一来源：`version.json` 定义产品版本，`PackageContents.xml`、`latest.json`、UI 常量、README 由构建/校验脚本对齐；修复 UI 版本漂移。
- 多版本 AutoCAD 打包：2014（R19.1）/ 2016（R20.1）/ 2024（R24.3）参数化构建与安装（已完成基础版）。
- CI 矩阵：Python 契约、MCP 握手、wheel、C# 契约在三个 AutoCAD 版本程序集上构建。

### B. Agent 现代化（约 2-3 周）

- `copilot_backend/agent/`：原生工具调用循环（本设计已落地第一版）。
- Planner v2：用 Agent Loop v2 替换 JSON 决策解析；保留计划、继续、重试、取消、回滚与事件协议。
- 技能编排：Skill 作为工具调用的编排层，任务完成 → Skill 草稿 → 验收样例运行。
- 流式事件与追踪：任务事件全链路 trace id，接入 OpenTelemetry。

### C. 知识增强（约 2-3 周）

- 分块 + 本地 embedding（Ollama 或企业 embedding 端点）+ 混合检索 + 重排。
- PDF/OCR 支持（docling/pypdf + OCR），来源引用 v2（条文号、版本、章节）。
- 文档权限分组（部门级隔离）。

### D. 几何内核与第二阶段 Skill（约 3-4 周）

- 引入 shapely 2.x；`cadmcp/domain/geometry/` 统一平面图、多边形化、偏移和中心线。
- 双线墙配对与中心线提取。
- 门窗开口识别与补口。
- 围合空间/房间识别与面积统计。
- 每个能力先只读验证 → dry-run → 受控写入，全部挂到 MCP 工具与 Skill 接口。

### E. 验收与发布（持续）

- 10 张真实 DWG 矩阵 D01-D10 + 人工标注 expected.json + 自动回归。
- wall/door/window Precision/Recall ≥ 85%，轮廓/图层任务成功率 ≥ 90%，写回滚 100%。
- 1.0.0-alpha 发布：Agent Loop v2 + RAG + 多版本包。

## 4. 版本策略

- 当前真实版本：0.9.0.622（本轮修复 UI 常量同步）。
- `cadmcp` 包版本独立演进（0.2.0 → 0.3.0，随工具扩展）。
- 桥协议保持 2.0；新增 Streamable HTTP 传输作为可选通道。
- 重新设计完成后发布 1.0.0-alpha（插件版本 1.0.0.0）。

## 5. 已落地的第一块（本设计随附实现）

- 版本常量修复：`UI/ChatPanel.xaml.cs` 由 0.8.0 → 0.9.0.622。
- 原生工具调用 Agent 循环：`copilot_backend/agent/loop.py`、`copilot_backend/agent/tools.py` 及单元测试。
