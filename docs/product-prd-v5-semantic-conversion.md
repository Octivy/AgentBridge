更新日期：2026-07-18
文档状态：当前产品主基线
适用范围：产品决策、阶段拆分、研发优先级、测试验收与对外口径

> v5.1 根据产品裁决进一步收窄：项目不再开发墙、门、窗等专业对象的创建与编辑工具，当前只建设 AutoCAD/天正图纸与 AI 模型之间的 MCP 连接、结构化读取、功能对象识别和少量安全 Skill。墙门窗专业工具与对象内核移出本产品路线，另行开发。

## 1. 最终产品定义

AgentBridge 不是新的天正，也不是在 AutoCAD 内重做一套墙、门、窗编辑器。

AgentBridge 是一个面向 AutoCAD 和天正图纸的 AI 连接与专业 Skill 系统：通过 MCP 让 Codex 和其他模型能够读取图纸、理解图层/图块/对象、调用受控 CAD 能力，并用可复用 Skill 完成专业任务。

一句话定义：

> 让 AI 通过标准 MCP 稳定读懂 AutoCAD/天正图纸，并安全调用专业 Skill 完成可验证的 CAD 任务。

第一阶段 MVP 的一句话定义：

> AI 连接当前 CAD 后，能够读取选定图纸，识别由图层线、普通块、动态块或天正对象表达的墙、门、窗等功能对象，并至少完成外围轮廓绘制和图层统一两项低风险任务。

## 2. 核心假设

核心假设：

> 只要 AI 能稳定获得真实 CAD/天正上下文，并通过少量可靠 Skill 执行操作，用户就能明显减少人工查看图层、辨认图块和重复整理图纸的时间，而不需要本项目开发完整的专业对象编辑器。

当前首先验证的风险不是“能否做出更多 CAD 工具”，而是：

1. 不同表达方式的图纸内容能否被统一读取和识别。
2. Codex 和其他模型能否稳定选择并调用正确 Skill。
3. AI 的识别证据、未知项和执行结果是否足够可信。
4. 两项最小任务是否真的比人工操作更快。

## 3. 产品边界

### 3.1 本项目负责

- AutoCAD 插件与本地桥接。
- 天正图纸的读取适配；优先支持可直接读取的对象、导出图元和转换后的普通图元。
- 面向 Codex 及其他模型的标准 MCP Server。
- 图纸快照、实体查询、图层、图块、对象类型和范围读取。
- 功能对象识别：把不同 CAD 表达统一解释为墙、门、窗、轮廓或未知对象。
- Skill 注册、选择、参数收集、执行、结果解释和验收。
- 少量通用、安全、可验证的 CAD 原子操作。
- 预演、授权、事务、验证、撤销和审计。

### 3.2 本项目不再负责

- 创建、编辑、连接、倒角、圆角、拆分或重建墙对象。
- 放置、翻转、删除或编辑门窗及墙洞对象。
- 复刻天正私有墙、门、窗对象格式。
- 建设完整墙体内核、门窗内核或天正命令替代系统。
- 以 MCP 工具数量作为产品目标。
- 第一阶段交付三维、BIM、IFC、Revit 或 Rhino 转换。

墙、门、窗仍然是第一阶段的只读识别对象，但不是本项目的创建和编辑对象。

### 3.3 独立开发内容

仓库中已经存在的墙、门、窗创建编辑工具、墙对象内核和相关技术文档视为独立专业工具线：

- 不再进入本产品 MVP 的排期、验收和对外能力清单。
- 不继续横向增加命令。
- 历史实现已经移到项目上一级备份区，不再参与当前编译、注册或测试。
- 如未来重启独立专业工具线，应使用独立包、独立仓库或独立插件，不回填当前连接器目录。

## 4. Tool 与 Skill 的重新定义

### 4.1 MCP Tool

Tool 是稳定、细粒度、可审计的内部原子能力，只供 Skill 和模型编排使用。

第一阶段保留的 Tool 类型：

- 连接：健康检查、能力发现、版本信息。
- 读取：图纸快照、选择集、实体查询、图层列表、图块列表、对象属性。
- 最小写入：绘制线/多段线、创建或调整图层、移动实体到目标图层。
- 安全：预演、授权、事务、验证、撤销。

第一阶段不新增墙、门、窗专业创建编辑 Tool。

### 4.2 Professional Skill

Skill 是面向用户任务的专业能力，内部组合多个 Tool、确定性算法和必要的模型判断。

第一阶段只交付四个 Skill：

| Skill | 作用 | 写图 |
| --- | --- | --- |
| 图纸理解 | 汇总图层、实体、图块、文字、范围和未知对象 | 否 |
| 功能对象识别 | 把图层线、块和对象统一识别为墙、门、窗或未知 | 否 |
| 绘制外围轮廓 | 从选定范围提取并在指定图层绘制最外轮廓 | 是，必须预演 |
| 统一图层 | 根据确认过的映射规则创建标准图层并迁移实体 | 是，必须预演 |

后续围合空间、面积统计、房间语义、图纸清理和批量转换都作为第二阶段 Skill，而不是继续扩展第一阶段工具箱。

## 5. 第一阶段 MVP 功能

### 5.1 AI 与 CAD 连接

- AutoCAD 插件、本地桥和 `cadmcp` 可以独立启动、发现和诊断。
- Codex 可以通过项目级 MCP 读取和调用当前 CAD。
- 其他支持 MCP 的 Host 可以直接接入。
- 不支持 MCP 的模型通过 Provider Gateway 和 Planner 间接使用相同能力。
- 模型供应商不可写死在业务逻辑中。

### 5.2 图纸读取

第一阶段读取范围：

- 图纸、空间、选择范围和单位。
- 图层名称、状态、颜色、线型和实体数量。
- LINE、LWPOLYLINE/POLYLINE、ARC、CIRCLE。
- TEXT、MTEXT、DIMENSION。
- 普通块和动态块的块名、有效名、插入点、旋转、缩放、属性和包围盒。
- 可访问的自定义对象运行时类型、图层、句柄和包围盒。
- 无法解析的代理对象和未知对象清单。

读取必须遵守：无法识别的对象也要返回类型、句柄和范围，不能静默忽略。

### 5.3 功能对象统一识别

第一阶段统一识别以下来源：

| 表达来源 | 示例 | 识别策略 |
| --- | --- | --- |
| 图层线图 | `A-WALL`、`WALL` 图层上的单线或双线 | 图层语义 + 几何特征 |
| 普通图块 | 门、窗、墙体组合块 | 块有效名 + 属性 + 图层 + 包围盒/可用几何 |
| 动态块 | 不同尺寸和可见状态的门窗块 | 动态块有效名 + 属性 + 变换信息 |
| AutoCAD/天正对象 | 原生或自定义墙、门、窗对象 | 运行时类型 + 可访问属性 + 适配器 |
| 导出/炸开图元 | 天正导出的普通线、弧、块 | 图层/块/几何组合识别 |
| 未知/代理对象 | 缺少相应 Object Enabler | 类型 + 包围盒 + 明确的 unsupported 状态 |

统一识别输出为 `FunctionalObject`：

```text
FunctionalObject
├─ id / source_handle
├─ semantic_type: wall | door | window | outline | unknown
├─ source_kind: layer_linework | block | native_object | proxy | unknown
├─ layer / block_name / runtime_type
├─ geometry_or_bounds
├─ evidence[]
├─ confidence
└─ support_status: supported | degraded | unsupported | needs_review
```

第一阶段目标是“能统一识别”，不是承诺所有天正版本和所有企业块库一次性达到相同准确率。实现按支持矩阵推进：先普通线和普通块，再动态块，再选定天正版本；某一对象格式难度过高时，允许降级为转换副本或 `unsupported`，但不得阻塞其他输入类型交付。

### 5.4 最小 Skill A：绘制外围轮廓

用户选择范围后：

1. 读取相关线、块和对象边界。
2. 生成外围轮廓候选。
3. 显示来源、面积、异常和预览。
4. 用户确认后在新图层绘制闭合多段线。
5. 验证实际写入并支持撤销。

第一阶段只承诺最外轮廓，不承诺房间净边界、门窗洞口扣除和完整面积统计。

### 5.5 最小 Skill B：统一图层

用户提供或确认图层映射后：

1. 读取现有图层和实体分布。
2. 根据图层名、块名和识别类型给出映射建议。
3. 未确认的映射不得执行。
4. 预演将创建、修改和迁移的图层/实体。
5. 用户确认后在一个事务中执行、验证并支持撤销。

“统一图层”不是只创建几个标准图层，还必须能够把选定实体迁移到确认后的目标图层。

## 6. 天正适配策略

天正图纸不能笼统声明“支持”，必须按版本和读取方式列出支持矩阵。

第一阶段采用四级策略：

1. 直接读取：安装相应环境后，读取可访问的天正/自定义对象类型和公开属性。
2. Object Enabler：在合法可用时通过对象支持组件获取更多属性。
3. 转换副本：在不修改原图的前提下，把选定对象导出或转换为普通图元后识别。
4. 降级报告：仍无法解析时，返回句柄、类型、图层、包围盒和明确原因。

第一阶段不做：

- 修改天正私有原生对象。
- 逆向或复制天正私有序列化格式。
- 承诺所有天正版本双向兼容。
- 为了一个特殊对象格式推迟全部 MVP。

## 7. 第一阶段标准用户流程

1. 用户打开 AutoCAD/天正图纸并连接 AI。
2. AI 调用连接诊断和图纸理解 Skill。
3. 系统返回图层、图块、标准实体、自定义对象和未知对象摘要。
4. AI 调用功能对象识别 Skill，显示墙、门、窗及其来源和置信度。
5. 用户选择“绘制外围轮廓”或“统一图层”。
6. Skill 收集缺失参数并生成预演。
7. 用户确认后执行写入。
8. 系统验证结果、生成任务报告并提供撤销。

AI 不得在未读取当前图纸的情况下猜测对象，不得把 `unsupported` 对象描述为已识别对象，也不得绕过用户确认执行批量图层迁移。

## 8. 第二阶段升级计划

第一阶段通过验收后，附加功能统一进入第二阶段，不提前塞入 MVP。

第二阶段候选 Skill：

- 双线墙与门窗开口形成的围合空间识别。
- 房间净边界、外围面积和房间面积统计。
- 房间名称、编号和文字匹配。
- 低置信度校核、合并、拆分和人工确认。
- 图层规则模板、企业块库词典和批量图纸整理。
- 更多天正版本、嵌套块和复杂动态块适配。
- JSON/SQLite 语义快照、版本和差异比较。
- 图纸识别结果转为标准功能图块或下游可消费的数据。

第二阶段仍不开发墙、门、窗创建编辑器。围合空间、面积和语义模型是读取与转换 Skill，不是专业对象绘制工具。

## 9. 后续阶段

### 第三阶段：二维到轻量三维

- 第一阶段不交付任何三维能力。
- 只有第二阶段形成稳定、经用户确认的语义数据后，才验证二维到轻量三维。
- 首次只选择一个目标格式或软件，不同时展开 Rhino、Revit 和 IFC。

### 第四阶段：跨软件转换

- 在单向转换稳定后考虑反向生成、版本差异和冲突处理。
- 连接器按真实用户工作流逐个增加。

### 第五阶段：专业与企业 Skill 平台

- 规则检查、指标、批处理、组织标准库、权限、审计和私有部署。
- 第三方可以增加 Skill，但不能绕过 MCP 安全边界。

## 10. 当前能力评估

### 10.1 已具备

- AutoCAD 插件、本地桥、backend、`cadmcp` 和模型网关基础。
- Codex 项目级 MCP 配置和其他 MCP Host 接入基础。
- 图层列表和详细快照。
- 普通块/动态块的名称、有效名、位置、旋转、缩放和属性读取。
- 直线、多段线、圆弧、圆、文字、标注和包围盒读取。
- 预演、授权、事务、验证和撤销基础。
- 单线/双线围合及外围轮廓算法原型。
- 图层标准创建/更新原型。
- Skill 注册和 Planner 选择机制原型。

### 10.2 部分具备

- `FunctionalObject` 契约、图层线/块/自定义/代理对象识别和显式支持状态已经实现并通过自动化测试，但尚未建立真实块库标注基准集。
- 动态块有效名、属性和变换信息可以读取，但动态参数、可见状态和嵌套图元尚未完整展开。
- 自定义/代理对象可以获得运行时类型、RXClass、DXF 名、范围和 Object Enabler 状态，但天正专业属性读取仍缺少版本适配器。
- 外围轮廓提取、面积、预演、闭合多段线落图和回滚代码闭环已经完成；块/自定义对象参与复杂轮廓和真实 DWG 成功率尚需验证。
- 图层映射建议、未知层保留、当前空间迁移（可按 Handle 限定）、复验和变更型回滚已经完成；跨布局和块定义策略不在当前 MVP 中。

### 10.3 尚不具备

- 对天正私有墙、门、窗对象的稳定语义读取。
- 跨天正版本的支持矩阵和自动兼容测试。
- 未安装 Object Enabler 时对代理对象内部参数的读取。
- 面向真实 DWG 的功能对象标注集和准确率报告。
- “外围轮廓”和“统一图层”两个 Skill 的真实 AutoCAD 2024 用户验收与效率数据。

### 10.4 已移出主产品

墙体创建、墙角处理、门窗放置和墙洞编辑等工具代码已经移到项目上一级备份区。当前仓库、默认 Skill、产品文档和第一阶段验收不再包含这些能力。

## 11. 第一阶段成功指标

### 11.1 测试集

- 至少 10 张真实 DWG，包含普通图层线、普通块、动态块和至少一种明确版本的天正图纸。
- 建立墙、门、窗和未知对象人工标注。
- 记录 AutoCAD/天正版本、Object Enabler、单位、块库和转换方式。
- 失败案例不得从统计中静默删除。

### 11.2 技术指标

| 指标 | 第一阶段最低门槛 |
| --- | --- |
| Codex MCP 连接与调用成功率 | 连续 20 次任务 ≥ 95% |
| 另一种模型/Host 调用成功率 | 连续 20 次任务 ≥ 95% |
| 支持的标准实体字段完整率 | ≥ 95% |
| 支持范围内墙/门/窗识别 Precision | ≥ 85% |
| 支持范围内墙/门/窗识别 Recall | ≥ 85% |
| 未支持对象显式报告率 | 100% |
| 外围轮廓 Skill 任务成功率 | ≥ 90% |
| 图层统一 Skill 任务成功率 | ≥ 90% |
| 原图损坏事件 | 0 |
| 已提交写入可撤销率 | 100% |

准确率必须同时声明数据集版本、支持范围和天正版本。`unsupported` 不是识别成功，但正确、完整地报告未知对象是合格的降级行为。

### 11.3 用户指标

- 至少 3 名种子用户用自己的图完成一次任务。
- 至少 2 名用户在一周内主动完成第二次任务。
- 图纸理解、外围轮廓或图层统一任务的总耗时至少降低 50%。
- 用户能够看懂识别证据、未知项和执行预览。

### 11.4 决策规则

- 坚持：连接稳定、识别达到门槛、两项 Skill 明显节省时间，进入第二阶段。
- 调整：某类对象难度过高时，缩小该对象的版本支持范围或使用转换副本，不扩大其他功能。
- 放弃/转向：AI 连接和 Skill 编排无法比现有脚本/人工流程降低成本，停止继续增加专业 Skill。

## 12. 当前开发优先级

截至 2026-07-21，`FunctionalObject`/代理诊断、两个写入 Skill、目录收口以及插件商业平台清障已经完成。当前优先级是先验证连接器基座，再投入真实 DWG 验证：连接器通过 Codex/第二 Host、多模型协议、错误恢复和安全门槛后，才执行真实图纸标注与失败样本硬化。当前交付见 [work-plan.md](work-plan.md) 和 [project-cleanup-2026-07-19.md](project-cleanup-2026-07-19.md)。

### 已完成：收口产品表面

1. 从默认产品 Skill 中移除墙、门、窗创建编辑能力。
2. 把已有专业对象工具标记为独立工具线/遗留能力，停止继续扩展。
3. 固化第一阶段四个 Skill 及其验收任务。
4. MCP 工具目录按连接、读取、最小写入和安全能力重新分组。

### 当前 P0：连接器基座验证

1. 固化插件、backend、`cadmcp`、本地桥之间的健康、工具和错误契约。
2. Codex 与至少另一种 MCP Host 分别完成连续初始化、工具发现和快照读取。
3. OpenAI 兼容与 Anthropic Messages 两类协议各验证一个真实 provider。
4. 验证重启、超时、错误 token、无效模型、限流和非 JSON 响应的诊断与恢复。
5. 确保白名单外工具、未授权写入和敏感配置泄露均为 0。

### 后续 P1：真实 DWG 与两个写入 Skill

1. 收集并人工标注至少 10 张真实 DWG，建立图层/块名词典和识别基线。
2. 使用真实 DWG 验证外围轮廓候选、面积、预演、落图和撤销。
3. 验证图层建议、未知层不映射、实体迁移、Handle 复验和变更型回滚。
4. 失败图纸必须保存脱敏快照并进入自动回归集。

## 14. 产品原则

1. 第一阶段只证明连接、读取、识别和两项最小 Skill。
2. 墙、门、窗是读取对象，不是本项目的编辑工具。
3. Tool 保持少而稳定，专业价值通过 Skill 组合表达。
4. 普通线、块、动态块和对象统一输出同一种功能对象契约。
5. 无法识别必须明确报告，不能静默忽略或让模型猜测。
6. 天正兼容按版本和适配方式声明，不使用模糊的“全面支持”。
7. 所有写入必须预演、确认、验证、可撤销，默认不修改原始对象。
8. 第一阶段不交付三维；附加功能通过验收后进入第二阶段。
9. 现有代码不等于产品范围，产品只承诺真实图纸和真实用户验证过的能力。
